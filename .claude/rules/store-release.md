- **Every release re-checks its store screenshots and previews against the build before submission (2026-10-03).** Full account: [docs/app-store-submission.md](../../docs/app-store-submission.md).
- Store screenshots sit beside `Support/AppStore/metadata.md` at the sizes App Store Connect accepts.
- Every listing image of one app reads as one app, because a set that flips between appearances reads as two; which appearance, and whether a frame breaks it on purpose, is the designer's.

## Xcode Cloud for a native Swift app (Undirect, worked 2026-11-21)

- Xcode > Integrate > Create Workflow makes the product (the API cannot); a project generated by xcodegen needs a committed `ci_scripts/ci_post_clone.sh` that runs `brew install xcodegen` and `xcodegen generate`.
- The default workflow builds on every push to main; PATCH `/v1/ciWorkflows/<id>` with `branchStartCondition.source.patterns: []` and ARCHIVE actions (`buildDistributionAudience: APP_STORE_ELIGIBLE`) makes it a hand-started release, then `POST /v1/ciBuildRuns` with the workflow and the main `scmGitReferences` id starts it (`Support/AppStore/cloud_build.py`).
- A manual run needs its branch in the workflow's start condition; a `filesAndFoldersRule` matching only `ci_scripts/release-trigger` keeps pushes from starting it.
- Build numbers: Apple's page says runs count from 1 and an existing Mac app sets Next Build Number by hand, but Undirect's second run (2026-11-21, already at build 15 in App Store Connect) was numbered 16 on its own. Read the run's `number` before assuming a setting is needed.
