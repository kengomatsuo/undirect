## 1. Read this first: what would make a real action fail

Ranked by how sure the failure is. "Fix" is what HQ should do instead.

| # | Action that fails | HQ | What Postiz (production) does / what the docs say | Fix |
|---|---|---|---|---|
| 1 | **Threads post or reply, image especially** | `threads.ts:46-52` `publish()` creates the container and calls `threads_publish` in the next line, no wait. Callers `threads.ts:58-60`. | Postiz polls the container `?fields=status,error_message` until FINISHED, then waits 2 s more, then publishes (`P:threads.provider.ts#L222-L248` loop, `#L194-L220` status read, `#L385-L407` publish). It treats error 4279009 "could not find the media container yet" as retry (`P:threads.provider.ts#L87-L93`). Meta says wait about 30 seconds before `threads_publish` (docs `/threads/posts`, step 2). | Split into two ticks: create the container, store its id in `hq_post_results` (or the reply row), return. The next minute's tick reads `status`; on FINISHED call `threads_publish`; on ERROR or EXPIRED stop with `error_message`. For text-only it is usually seconds, but do not publish in the same invocation. |
| 2 | **Instagram post** | `meta.ts:106-118`: create container, then call `media_publish` up to 4 times, 2 s apart, retrying on any error. | Postiz reads the container `?fields=status_code,status` (`P:instagram.provider.ts#L674-L710`) and publishes only when it is not IN_PROGRESS (`#L918-L983`). Meta: query once a minute for at most 5 minutes; values EXPIRED, ERROR, FINISHED, IN_PROGRESS, PUBLISHED (docs `/instagram-platform/content-publishing`, "Container publishing status"). Postiz also handles `media_publish` answering "blocked" (2207051) while the post is live: it asks the container if it is PUBLISHED and fetches the media id (`P:instagram.provider.ts#L1088-L1105`, helper `#L714-L750`). | Same two-tick design as row 1, keyed on `status_code`. Never retry `media_publish` blindly: a permanent error burns 8 s then fails, and a "blocked" answer on a live post makes HQ show failure and the owner repost, which duplicates. After any `media_publish` error, read `status_code`; if PUBLISHED, fetch `/{ig-id}/media?fields=id,permalink&limit=1` and record success. |
| 3 | **Anything that waits inside one invocation** | `jobs.ts:131-137` `sendAfterUndoWindow` sleeps 10.5 s then runs `sendDueAnswers` and `sendDuePost` inside `ctx.waitUntil`. `jobs.ts:118` inserts the `hq_post_results` row before the call. Add what Postiz adds: a result row that is `sending` with no `platform_id` and older than the reclaim window must show "may already be posted, check the account", never be retried (copy the sentence idea from `P:x.provider.ts#L918-L925`). Replies have no reclaim at all: `jobs.ts:85` sets `answer_status='sending'` and nothing resets one that died. |
| 4 | **Instagram image that is not a JPEG** | `routes.ts:71-76` accepts JPEG, PNG, WebP, GIF up to 8 MB and the Worker serves it as uploaded (`index.ts` media route). `meta.ts:106` passes it to Instagram. | Meta: "JPEG is the only image format supported" for publishing (docs `/instagram-platform/content-publishing`, Limitations). Postiz has a `convertToJPEG` flag only on TikTok (`P:tiktok.provider.ts#L40`), so how Postiz copes with a PNG on Instagram is UNSURE. | Accept JPEG only at upload (or convert in the browser with a canvas before upload) and cap at 4 MB so one file is valid on IG, FB, Threads and X. The message in `routes.ts:76` says 8 MB is Instagram's limit; that is the Threads number. |
| 5 | **X mentions or own-post read** | `x.ts:74` asks `tweet.fields=created_at,public_metrics,non_public_metrics` for the last ten posts. | X docs: non-public metrics exist only for posts created in the last 30 days, and the non-public list has no impression count (`docs.x.com/x-api/fundamentals/metrics`: Impressions is `public_metrics.impression_count`). Add: on a failed refresh answer `invalid_grant`, set a "reconnect X" flag and stop trying every minute; today each tick spends a subrequest and X sees repeated bad refreshes. ## 3. Where HQ is already right and Postiz is not

- `ctx.ts:46` treats TikTok `error.code: "ok"` as success.
- IG comment authorship check by username (`meta.ts:63`); the fork says it has no reliable way (`F:instagram.provider.ts#L705-L708`).
- X rotating refresh token stored before the access token is returned, with a lock (`x.ts:20`, `tokens.ts:39-68`).
- A result row is written before every post call and an account already recorded is never posted again (`jobs.ts:113-118`); the Postiz equivalent is the arm-confirm handshake (`P:x.provider.ts#L1295-L1305`).
- X read bills each resource once per UTC day and reads only newer mentions (`x.ts:28-36, 72-92`).
